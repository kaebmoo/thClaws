# Media generation

Provider-abstracted image, video and speech generation. One trait per
medium, a registry that maps a model string to its provider, and shared
output helpers — so a generation the model triggers and one the user
clicks in Media Studio take the same code path, write the same bytes and
bill identically.

Source: `crates/core/src/media/` — `provider.rs` (the traits),
`registry.rs` (model → provider resolution), `job.rs` (the async video
job store), `providers/` (the backends), `mod.rs` (format sniffing and
output).

## 1. The seam

```
  TextToImage / ImageToImage      Media Studio (GUI shell)
  TextToVideo / ImageToVideo               │
  MediaJobStatus / TextToSpeech            │
        │                                  │
        └──────────────┬───────────────────┘
                       ▼
              media::registry::resolve*
                       ▼
        ImageProvider / VideoProvider / SpeechProvider
                       ▼
     gemini · openai · qwen · iapp · veo · ltx · dashscope_video
```

The tools in `tools/image_gen.rs` and the Studio shell are both thin
callers. That is deliberate: the point of the seam is that there is no
"GUI path" that could drift from the "agent path".

## 2. Three traits, three shapes

| Trait | Request | Returns |
|---|---|---|
| `ImageProvider` | `ImageRequest` (+ optional `InputImage` for edits) | `ImageResult` — bytes, synchronously |
| `VideoProvider` | `VideoRequest` | A `JobState` — the work is asynchronous |
| `SpeechProvider` | `SpeechRequest` | `SpeechResult` — bytes |

Images and speech return bytes in the call. Video does not, because it
cannot: Veo takes 30–120 seconds, which is longer than any sensible tool
call.

## 3. The async video job model

`TextToVideo` / `ImageToVideo` **submit** and return a `job_id`.
`MediaJobStatus` polls it.

State is persisted to `.thclaws/state/media-jobs.jsonl` — append-only,
latest line per id wins — so a poll survives an engine restart. The
provider-side operation reference outlives our process; on restart we
just re-attach to it rather than losing the render.

```jsonc
{
  "id": "…", "kind": "text2video", "provider": "veo", "model": "…",
  "op": "<provider-side operation ref>",     // what a poll re-attaches to
  "status": "…", "asset_path": "…", "error": null,
  "duration_seconds": 8, "created_at": "…"
}
```

The store re-reads the file on every call and serialises through a
process-global mutex. Volume is a handful of jobs, so there is no
in-memory cache — and therefore no cache that can diverge from disk.
Resume is just "read the log".

## 4. Output

`save_image` / `save_video` / `save_audio` hash the bytes with SHA-256
and write to `<workspace>/output/` under a content-derived name, then
return the **relative** path. Content addressing means regenerating the
same bytes does not litter the folder with duplicates.

Writes go through `Sandbox::root()` when there is one, so output lands
inside the workspace rather than wherever the process happens to be.

### Format is sniffed, not assumed

Generated bytes are not always what the API documentation implies —
Gemini flash frequently returns JPEG where PNG was requested, and
mislabelling it breaks every downstream consumer. `mod.rs` sniffs magic
bytes:

- images — by signature;
- video — ISO-BMFF (`ftyp` at offset 4) → `mp4`, Matroska magic → `webm`, else `mp4`.

## 5. Backends

`providers/` holds `gemini`, `openai`, `qwen`, `iapp` (images),
`veo`, `ltx`, `dashscope_video` (video). `registry::resolve`,
`resolve_video` and `resolve_speech` map a `(provider, model)` pair to
an implementation and the canonical model id; `list_models` enumerates
what the Settings and Studio pickers show.

Adding a backend is a new file in `providers/` plus a registry arm —
the tools and the Studio shell do not change.

`iapp` is worth knowing about specifically: it is the one image backend
that *typesets* Thai text rather than leaving the diffusion model to
draw glyphs, which is what stops Thai script coming back mangled.

## 6. Things to watch

- **The job log lives in the state tier**, so all three filters that key on `state` cover it: the publish strip, the deploy uploader's `NEVER_SHIP`, and the pod-side `PRESERVE_ON_POD`. It has not always: until it moved, publishing a catalog agent shipped the log, and deploying an agent update to a pod *overwrote* it, losing the operation refs of any render still in flight. Legacy workspaces migrate on next open via `LEGACY_STATE_ENTRIES`; `STRIP_EXACT` keeps a transitional entry for one that has not been opened since.
- **Video jobs outlive the session.** A `job_id` from yesterday still polls, which is the point, but it also means the log grows and is never pruned.
- **Gateway metering is per-provider.** Media calls are metered on the thclaws.cloud gateway with per-provider rules — Kie bills on `creditsConsumed` returned by the poll, not on submission. See [`provider-thclaws-gateway.md`](provider-thclaws-gateway.md).
